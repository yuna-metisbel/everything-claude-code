# 不具合の受け口（ひな形）

渡した会社から「動かない」と言われたときに、どこで受けて、何を聞いて、
どう切り分けるか。〈 〉を埋めて、導入先に渡す。

窓口の文字列は `config.js` の `support` に入れる。入れると、
「設定」タブの**困ったとき**と、画面が出ないときのエラー表示に出る。
空のままだと何も出ない（嘘の窓口を出すより、出さないほうがまし）。

```js
support: "〈担当者名〉 / LINE: 〈ID〉 / 〈メールアドレス〉"
```

---

## 導入先に渡す案内

### 連絡する前に、これだけ試してください

半分くらいはこれで直ります。

1. **ページを再読み込みする**（スマホは下に引っ張る）
2. **電波のいい場所で開く**。地下や電波の弱い場所だと読み込めません
3. **一度ログアウトして、入り直す**
4. **ほかの人の端末でも同じか**を見る
   - ほかの人も同じ → ボード側の問題。連絡してください
   - 自分だけ → その端末かブラウザの問題の可能性が高いです

### 連絡するときに書いてほしいこと

これが無いと、こちらでは何も調べられません。

- **誰が**：本部の人か、どの店舗のスタッフか
- **いつ**：日付と、だいたいの時刻（「今日の15時ごろ」で十分）
- **どの画面で**：ホーム／予定／タスク／支払い／拠点／設定、など
- **何をしたら**：どのボタンを押したか
- **どうなったか**：画面に出た文字をそのまま。読めるなら画面の写真
- **端末**：iPhone か Android か、ホーム画面に置いたものか、ブラウザで開いたか

**暗証番号やパスワードは書かないでください。** こちらで調べるのに要りません。

### 急ぎのもの

次は見つけた時点ですぐ連絡してください。

- **ログインできない人がいる**（止まっている可能性があります）
- **ほかの人の情報が見えている**
- **入り口の URL が外部に出た**
- **消してしまって、戻せない**

## 受ける側の手順

### 1. どちらの問題か切り分ける

| 症状 | 先に見るところ |
|------|---------------|
| 全員が開けない | Supabase のプロジェクトが止まっていないか（[BACKUP.md](BACKUP.md) の1） |
| 画面が真っ白／「設定がありません」 | `config.js` が配信されているか |
| 「読み込めませんでした」 | jsDelivr（部品の配信）に届いているか。回線のことが多い |
| 1人だけ入れない | その人が「利用停止」になっていないか、入り口が公開されているか |
| 通知が来ない | `push_config` の3つ（`function_url` / `anon_key` / `send_secret`）、`push_log` に行があるか |
| 見えるはずのものが見えない | その項目の公開範囲。`share` / `open_sites` |
| 保存したのに消える | 読み込みの失敗。画面の上に帯が出ていないか |

### 2. 止まっているかの確認

Supabase のダッシュボードでプロジェクトの状態を見る。
`PAUSED` なら **Resume project**。止まってから90日以内なら戻る。

**Free は7日間使われないと止まる。** 渡した会社が試して放置すると起きる。
これが原因だったときは、Pro にするかどうかを一緒に決める（[BACKUP.md](BACKUP.md) の2）。

### 3. 通知が来ないときの確認

```sql
-- 宛先が入っているか
select coalesce(function_url, '') <> '' as url_set,
       coalesce(anon_key, '')     <> '' as key_set,
       coalesce(send_secret, '')  <> '' as secret_set
  from public.push_config where id = 1;

-- 送った記録があるか（新しい順）
select tag, title, sent_at, ok_count, fail_count
  from public.push_log order by sent_at desc limit 10;

-- 通知を入れた端末の数
select count(*) as devices from public.push_subs;
```

`ok_count` が 0 で `fail_count` が立っていれば、端末側で通知が切られている
可能性が高い。`push_log` に行が無ければ、送る前で止まっている。

### 4. 返事の目安

〈 〉営業日以内に一次返答。無償のうちは、期限内の修正は約束しない
（[TERMS.md](TERMS.md) 第4条）。

直せないときは、直せないことと、代わりにできることを返す。
黙って放置するのが一番よくない。

### 5. 同じことが続いたら

同じ問い合わせが3回来たら、それは問い合わせではなく**直すべきもの**。
受け口で捌き続けず、画面の文言か作りを変える。

## 範囲外にすること

[TERMS.md](TERMS.md) 第4条と揃えておく。

- 利用者の操作による誤入力・誤削除の復旧
- 端末・回線・ブラウザに起因する不具合
- Supabase、Render、Google、Apple などの障害
- 利用者が独自に加えた変更
